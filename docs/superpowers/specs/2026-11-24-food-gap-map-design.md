# Карта продовольственного разрыва — дизайн

Дата: 24.11.2026. Конкурс X5 «Вайбкодинг добрых дел». Адресат: благотворительный фонд X5 «Выручаем».

## Проблема

Фонд и МГУ (2026, 81 регион, 30 лет данных Росстата) показали: +1 кг продуктовой помощи на душу населения в год связан со снижением уровня бедности в регионе на 20,55 % при прочих равных. Значит, важно, **куда** попадает следующий килограмм.

Сейчас помощь в основном остаётся там, где её собрали. Пресс-релизы X5 это подтверждают: в 1 полугодии 2025 «Корзина доброты» собрала в Воронеже 22,9 т, а в Новосибирске 0,2 т; 111 из 195 т фудшеринга «Пятёрочки» пришлись на Мурманск. Платформа продпомощи (12.2025) прямо описана как способ «направлять помощь точечно в те регионы, где она была собрана». Магазины X5 сосредоточены в богатых регионах Центра, а доля малоимущих выше на Кавказе, в Сибири и на Дальнем Востоке. Публичного инструмента, который сводит нужду и присутствие помощи на одной карте, нет ни у фонда, ни у X5, ни в РФ.

## Решение

Открытое веб-приложение без установки и без сервера: карта 85 субъектов РФ, где нужда (Росстат) сопоставлена с присутствием X5 и объёмом помощи, плюс три калькулятора для решений фонда.

### Пользователи и задачи
1. **Программный директор фонда:** куда направить нецелевые пожертвования (онлайн, софинансирование), чтобы эффект был максимальным.
2. **GR и руководство фонда:** региональные цифры для законопроекта об освобождении фудшеринга от НДС.
3. **Аналитик платформы продпомощи:** загрузить свою выгрузку по регионам и увидеть реальный разрыв.
4. **Партнёры, НКО, журналисты:** понятная публичная карта с источниками.

### Экраны (одна страница, разделы с якорями)
1. **Карта.** Плиточная карта России (85 субъектов, одинаковые клетки, примерно на своих местах): мелкие регионы видны наравне с крупными. Слои: «Разрыв» (по умолчанию), «Уровень бедности», «Малоимущих, тыс. чел.», «Стоимость минимального набора продуктов», «Магазины X5». Клик по региону открывает карточку: все показатели с годом и источником, место в рейтинге, известные факты о помощи в регионе из пресс-релизов X5.
2. **Распределение суммы.** Ввод суммы (₽) и стратегии: «Как сейчас» (пропорционально магазинам X5, где собрали, туда и отдали), «По нужде» (пропорционально числу малоимущих), «Выровнять разрыв» (сначала регионы с наименьшим числом кг на малоимущего). Результат: таблица регионов (₽, кг, ожидаемое снижение числа малоимущих по коэффициенту МГУ), итог и сравнение с «Как сейчас». Выгрузка CSV.
3. **Сценарий «Без НДС».** Рост объёма помощи (по умолчанию +40 %, минимальная оценка МГУ; ползунок до +200 %) -> доп. тонны по регионам и ожидаемый эффект. Текстовая «справка для GR» с цифрами, которую можно скопировать или распечатать.
4. **Свои данные.** Загрузка CSV/XLSX выгрузки платформы (регион + кг за период). Регион распознаётся по названию, коду ISO или ОКАТО. Файл обрабатывается только в браузере и никуда не отправляется. После загрузки карта и калькуляторы считают по факту, а не по модели. Есть шаблон для скачивания.
5. **Методика и источники.** Формулы, допущения, ограничения, ссылки на первоисточники, дата выгрузки.

Росстат публикует уровень бедности по 85 субъектам без учёта новых субъектов. Карта показывает эти 85 и прямо пишет об этом в методике. Для Архангельской и Тюменской областей берутся строки «без автономных округов», АО считаются отдельно.

Rosstat.gov.ru отдаёт файлы только браузеру, поэтому загрузчик берёт те же ряды Росстата через официальную витрину ЕМИСС (fedstat.ru). Ответы ЕМИСС (SDMX) лежат в `data/raw` вместе с запросами.

## Модель
- Малоимущие: `poor_r = rate_r × pop_r`.
- Индекс цен: `p_r = basket_r / basket_РФ`; цена 1 кг помощи в регионе: `price_r = price_РФ × p_r`.
- Помощь «как сейчас» (модель, если нет выгрузки фонда): `aid_r = V × stores_r / Σ stores`.
- Покрытие: `cov_r = aid_r / poor_r` (кг на малоимущего в год). **Разрыв** = `cov_r / cov_РФ`: меньше 1 значит, что помощи меньше, чем в среднем по стране на одного малоимущего.
- Эффект (коэффициент МГУ как полуэластичность): `Δpoor_r = poor_r × (1 − exp(−0,2055 × Δkg_r / pop_r))`. При малых объёмах это ≈ `0,2055 × rate_r × Δkg_r`, то есть эффект одного килограмма пропорционален доле бедных.
- Стратегии распределения суммы S: ₽ -> кг по `price_r`. «Как сейчас»: ∝ stores_r. «По нужде»: ∝ poor_r. «Выровнять разрыв»: water-filling по `cov_r`, сумма уходит регионам с наименьшим покрытием, пока они не догонят следующие.
- Везде оговорка: коэффициент МГУ описывает статистическую связь, а не гарантированный эффект. Модель помогает сравнивать варианты между собой, а не обещает точное число людей.

## Архитектура
- `data/` (Python 3.12, без тяжёлых зависимостей): `emiss.py` (клиент ЕМИСС), `osm_x5.py` (магазины), `build.py` -> `public/data/regions.json` + `public/data/sources.json`. Тесты: pytest на сборку (85 регионов, суммы, диапазоны).
- `src/` (Vite + React + TypeScript, статика):
  - `model/`: чистые функции `metrics.ts` (покрытие, разрыв), `allocate.ts` (3 стратегии), `effect.ts` (МГУ), `vat.ts`. Без React, полностью покрыты Vitest.
  - `io/`: `parseUpload.ts` (CSV/XLSX -> строки), `matchRegion.ts` (название/ISO/ОКАТО -> регион, нормализация «г.», «Республика», ё/е, АО), `exportCsv.ts`.
  - `ui/`: `TileMap` (SVG), `RegionCard`, `LayerSwitch`, `Allocator`, `VatScenario`, `Upload`, `Method`.
  - Состояние: React state + синхронизация ключевых параметров в URL (регион, слой, сумма, стратегия), чтобы ссылкой можно было поделиться.
- Деплой: GitHub Pages через GitHub Actions (тесты -> сборка -> публикация).

## Ошибки и крайние случаи
- Регион без данных (ни в одном источнике): серая клетка «нет данных», в расчётах не участвует.
- Нераспознанные строки загрузки: список с подсказками и ручным выбором региона. Расчёт идёт по распознанным, неразобранные строки не теряются молча.
- Ноль магазинов в регионе: покрытие 0, разрыв максимальный, отдельная пометка «X5 не присутствует».
- Пустая или нулевая сумма: калькулятор показывает подсказку, а не NaN.

## Тестирование
- Vitest: модель (инварианты: сумма распределения = S; «выровнять» не ухудшает минимум покрытия; эффект монотонен по кг), разбор загрузки, сопоставление регионов (все 85 официальных названий Росстата и типичные варианты).
- pytest: сборка данных.
- Проверка глазами: gstack browse, десктоп и телефон, скриншоты.

## Вне рамок (YAGNI)
Бэкенд и аккаунты; муниципальный уровень; прогнозы бедности; интеграция с API платформы (её нет публично, вместо неё загрузка выгрузки).
